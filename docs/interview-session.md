# Interview session frontend

Start Interview validates the setup and creates a session at `/interview-simulator/session?id=<id>`. The simulator home links to the unfinished session. Starting a different session requires choosing to resume the existing one or explicitly ending it early and starting a new one.

## Persistence and time

The asynchronous repository stores sessions in the `ai-career-interviews` IndexedDB database. It retains configurations, question content, submitted and skipped answers, unfinished drafts, status, timestamps, and completion reasons after navigation, refresh, and tab closure in the same browser profile and origin. Writes commit in IndexedDB transactions. A failed write leaves the prior record intact. A browser that blocks or clears site storage, uses temporary private storage, or exceeds its quota may prevent saving or remove local records.

Each record is scoped to the current local interview workspace. The app's sign-out flow rotates that workspace, so prior records are no longer shown in the new workspace. Setup drafts stay in the originating tab and workspace. Unbound legacy copies are accepted only in the original local workspace. This is browser-local separation. The app has no authenticated identity to associate a record with an account or recover it across browser profiles, devices, or origins.

On first access from a tab with STEP 06 session data, valid legacy records are imported under their original IDs and configurations. Existing IndexedDB records take precedence when the same ID exists. The legacy key is removed only after all its records have been imported or matched in a committed transaction. Invalid entries and divergent copies are retained in the source tab, and a failed migration leaves the source available for retry. A legacy record from a tab that was closed before migration cannot be recovered. If multiple tabs hold distinct legacy unfinished interviews, migration preserves them and the simulator resumes the latest eligible one.

An available first question starts the timer. A running session continues timing when the user leaves or waits for a later question. Pausing freezes elapsed time until resume. The application calculates remaining time from persisted timestamps, and reconciles time expiry when reopening a session after a background interval. Unlimited sessions display elapsed time. The browser may require a user gesture before showing its refresh or close confirmation. Confirmed in-app exit waits for the most recent draft write. A stale-tab write to a question that has advanced or paused is rejected and leaves the text in that tab for copying. Concurrent edits to the same current draft use the last successful write.

## Question provider

The frontend requests one question at a time. The adapter receives the session ID, complete interview configuration, zero-based question position, stable request key, abort signal, and ordered history of question content and outcomes. Only submitted answers are included in this history. Skips are identified and unfinished drafts stay local. The provider can return an available question with a stable ID, category, content, and source, or report that the question is pending or unavailable. Failures and pending responses can be retried for the same position. A follow-up can identify an earlier answered question using `followUpTo`. The session persists this relationship with the delivered question.

The local production provider delivers user-authored questions in order and counts them toward the configured total. After those questions, the local provider returns unavailable. An injected provider owns sequencing, including placement of user-defined questions.

## STEP 11 adaptive AI contract

The future interviewer can generate, select, reorder upcoming questions, and adjust topics, wording, and follow-ups as the session progresses. It can use previous submitted answers to clarify, probe, or change direction. Evaluation can consider the questions actually delivered and the answers actually submitted. Generation and evaluation operate within the user's selected types, focus areas, difficulty, language, duration, question budget, and custom instructions. The interviewer can decide each next question during the session without requiring a precomputed question list or a predefined question bank. Previously delivered questions retain their IDs and recorded order.

The backend must authenticate the caller, resolve their workspace and session, verify authorization for each data source, and use only relevant, permitted context. Eligible sources include User Profile, CV Builder, Career Test Results, My Skills, Career Match, Interview History, Previous Interview Answers, Job Description, Interview Configuration, and Custom Instructions. The frontend adapter context is local application data, and the future network transport should identify the session and expected position or revision so the backend can resolve authoritative history and source permissions. The backend must independently enforce data isolation, privacy permissions, timing and pause rules, question limits, and session integrity. It should return the same committed question for a repeated request key and reject stale transitions. STEP 11 owns the authenticated transport and AI integration.

To exercise the full lifecycle locally, start Vite with `VITE_INTERVIEW_DEV_FIXTURES=1 npm run dev` from `frontend`. Prompts are labeled as development fixtures and are excluded from production builds. Completed sessions link to `/interview-simulator/results/:sessionId`. Results compute statistics from submitted answers and saved timing. The review includes delivered questions only, while overall statistics include the configured total. Unfinished text appears separately from submitted answers. Download Report opens the browser print dialog, where Save as PDF exports all delivered questions and answers, independent of screen filters.

Results use a separate evaluation-provider interface. Production currently returns an explicit unavailable state. For UI verification only, set `VITE_INTERVIEW_EVALUATION_FIXTURES=1` when running Vite in development. Retake restores the original configuration into the corresponding editable setup draft and creates a new session when started. Cloud synchronization remains pending.

## Interview History

`/interview-simulator/history` and Recent Interviews read the same local workspace records. History reconciles expired interviews on load. The Completed Interviews statistic counts all finalized records, including early ends and timeouts, while the status filter distinguishes the three completion reasons. Practice time uses saved session timing. Date filters use local calendar dates, and average scores include only validated completed evaluations saved with finalized sessions. Evaluation data stays separate from session statistics.

On deletion, the repository removes the interview content and any associated evaluation in a single transaction. It retains the workspace and deleted ID as a tombstone to prevent a legacy tab from re-importing the deleted record. Bulk deletion applies to the entire workspace regardless of the current filters. Active and paused sessions require an additional opt-in. Record lists reload when navigating back or refocusing the tab.

Retake restores only the saved setup, including user-authored questions. It creates a fresh session and leaves a future adaptive interviewer free to choose new questions. STEP 11 may use historical context only after the backend authenticates the requester and applies the data-source permissions described above.

## Progress & Performance

`/interview-simulator/progress` reads the same workspace records as History and refreshes on navigation or tab focus. Time, interview type, job role, and difficulty apply to the analytics, activity, and comparison candidates. Interview dates use the local calendar date of the session start, or the creation date if it never started. Seven-, 30-, and 90-day filters include today. Month and year filters use rolling calendar boundaries with end-of-month clamping. The previous equivalent period is the immediately preceding range with the same number of local calendar days. Open-ended ranges have no previous-period comparison.

Average and best scores use validated completed evaluations. Missing or invalid scores are excluded, and a validated zero is included. Score change is the latest minus earliest comparable score. Previous-period change compares averages and requires comparable evaluations in both periods. Trends and interview score differences require the same interview type, Custom type mix, difficulty, and explicit scoring methodology ID and version. Individual scores may still be shown when trend comparison is unavailable. The score chart is ordered by interview date. Lines break at unavailable scores or incompatible methodologies. The running-average series uses comparable observed scores. Best-performing type is shown only for a unique leader with a shared methodology and difficulty across evaluated types.

Category IDs are canonical identifiers derived from the approved category labels. Repeated category scores are aggregated only within a shared, explicit scoring methodology. The radar chart requires at least three plottable categories that share a methodology. Category changes use the first and latest compatible observations. These metrics reflect interview performance. The analytics never writes to My Skills or profile data.

A meaningful practice session has at least one submitted answer. Activity groups each such session once by its local start date, or creation date if no start is available. Weeks start on Monday. The current streak counts consecutive local practice dates ending today, or yesterday if today has no qualifying practice. The longest streak is the longest consecutive run in the filtered dates. A date counts once regardless of how many interviews were practiced that day. Skipped-only and empty sessions never add a practice day. Interviews completed this week are qualifying sessions with all questions handled and a completion timestamp in the current local Monday–Sunday week. Activity duration uses elapsed time for qualifying sessions. The overview's total practice time sums elapsed time for all matching sessions, even if they have no submitted answers.

Practice recommendations require validated provider-supplied focus entries. Retake uses only the saved configuration and keeps the original results. The asynchronous coaching interface reserves AI insights and an editable, evolving practice plan for STEP 11. Production analytics shows unavailable evaluation and coaching states while those services remain disconnected. Scored chart rendering, score tooltips and point navigation, populated radar charts, and evaluation-driven practice actions still require authorized end-to-end data in STEP 11. The calculations can be checked without browser data using `node --test frontend/tests/interview-progress.test.mjs`.
